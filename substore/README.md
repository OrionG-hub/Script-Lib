# Sub-Store 重命名脚本

`rename.js` 按机场和国家/地区分组，生成“国旗 地区缩写 序号 [倍率] [DIP] - 机场名”，保留实验性节点和 EMBY 规则。

## 性能

- 地区别名按边界类型分为两组，并在组内按长度和原始优先级编译联合正则，避免每个节点逐条运行所有别名正则。
- 同一脚本运行环境、同一个公共工具对象复用编译后的识别器；不会跨进程缓存节点结果，也不会缓存订阅输出。
- 保持原识别语义：最早位置优先、同位置最长别名优先、完全相同时按原别名顺序；保留拉丁边界、地区短码位置限制和国旗回退。
- 不改变节点排序、机场分组、编号、倍率、独享 IP 和不可识别节点的处理方式。

## 验证边界

已用原实现对照地区识别和完整 operator 输出，包含多语言别名、大小写、边界、重叠名称、缺少 Intl、国旗回退及无效节点。测试中的公共工具由替身提供；真实 Sub-Store/Surge 环境及远端 common.js 的集成仍需部署后验证。

本地 Node.js 的匹配基准不包含订阅下载、远端公共脚本获取和宿主应用开销，不能直接等同于订阅刷新提速比例。

本次对照 30,150 个名称均与原实现一致；关闭覆盖率后的 5000 名称暖机基准（5 轮中位数）从 124.8 ms 降至 14.1 ms。独立 V8 覆盖率采集记录到 `rename.js` 的 28/28 个函数被执行；这是函数覆盖率，不代表所有分支、宿主环境或 Shell 脚本均已覆盖。
